## 2. 1361 averagePrice는 단순평균

`averagePrice`는 거래량 가중평균이 아니라 **같은 날 시장·법인 행 가격의 단순평균**입니다(1362 대조: 행 단순평균과 차이 중앙값 0.0%, 거래량 가중과는 10~12%). 거래량·금액 합계는 정확히 맞습니다. 그래서 0.06톤 행과 32톤 행이 같은 무게로 평균에 들어갑니다.

앱이 하는 일: 반월 안에서 `averagePrice`를 그날 1361 거래량으로 가중합니다(`stab_price_basis = 1361_averagePrice_반월가중`). 물류비는 같은 방식의 월 평균입니다.

종이에서의 뜻:
- 이 값은 도매시장 실제 거래가(금액÷거래량)와 다를 수 있습니다. 2025-26 1~3월에 1361 값이 가락보다 약 10% 높았습니다(1,160 vs 1,050).
- 그래서 판정은 값 하나로 자르지 않고 "아래 / 근처 — 농협 확인 / 위" 세 갈래로 하며, 근처는 단정하지 않습니다(3-2).
- 앞으로 금액÷거래량으로 바꾸면 경계를 다시 보정해야 합니다(`params_by_season.csv`의 `stab_price_basis` method에 기록).

> **데이터 메모 주의(2026-11-10 정리)**
> - `crops.csv`의 당근 `judge_source=hub1362_garak`과 그 메모("1361 averagePrice는 행 단순평균이라 쓰지 말고 금액/거래량 사용")는 **낡은 글**입니다. 실제 판정은 코드(`app/core/triggers.py`)와 `params_by_season.csv`가 정하며, 종이에 쓰이는 값은 1361 `averagePrice`를 반월 거래량으로 가중한 것입니다. 양배추 행도 같습니다.
> - `params_by_season.csv`의 구간 설명은 기준 기간을 "2017-01~2021-08"로 적었지만, 저장본 `agg_869_ratio.csv`는 2021-03-31에 끝납니다(42개 반월). **저장본 날짜가 맞습니다.**
> - 두 CSV의 메모 문구는 설명용 주석이며 판정 코드는 읽지 않습니다. 코드와 저장본 날짜가 기준입니다.
> - `cli.bat <명령>`은 `python -X utf8 -m app.cli <명령>`의 묶음 파일입니다. 시스템 Python만 있을 때는 `python -X utf8 -m app.cli …`로 같은 명령입니다.

## 3. 경계 구간

### 3-1. 면적·나이 구간 (유형별 종이)
`app/core/typesheet.py`가 구간의 **가장 불리한 쪽 하한**으로 계산해, 종이가 금액을 부풀리지 않게 합니다.

| 구간 | 코드 값 | 대표 값 | 근거 |
|---|---|---|---|
| 면적 | `le_0_5ha` / `0_5_to_1ha` / `gt_1ha` | 1,000㎡ / 5,001㎡ / 10,001㎡ | 경영체 등록 하한 1,000㎡, 소농직불금·면적직불금의 0.5ha·1ha 경계(`supports.csv` 면적 칸) |
| 나이 | `lt60` / `60_64` / `65_74` / `75_84` / `ge85` | 50 / 60 / 65 / 75 / 85세 | 구간의 가장 적은 나이(60세 미만은 50세로 가정). `supports.csv`의 min/max_age, 출생일 조건 |

종이에는 "구간의 가장 작은 밭·만 ○세 기준"이라고 적고, 1,000평 예시는 따로 보입니다.

### 3-2. 가격 구간 (가격안정관리제)
기준가 × **0.911** 미만 "아래", × **1.143** 이상 "위", 사이는 "근처 — 농협 확인".
- 근거 행: `agg_869_ratio.csv`(당근 일반, 2017-01~2021-03 11~3월 반월 42개)의 가락/1361 비를 `app/data_layer/snapshot.py`의 `_ratio_bounds`와 같은 방법(`statistics.quantiles(n=10, method="inclusive")`)으로 다시 계산하면 p90 = 1.0977, p10 = 0.8746 → 1/1.0977 = 0.911, 1/0.8746 = 1.143(2026-11-11 저장본 재계산). 표 값과 재계산값이 같은지는 `tests/data/test_band_consistency.py`가 고정합니다. 시즌값 표 행: `params_by_season.csv`의 `stab_band_lo`, `stab_band_hi`(당근 등급 "계산").
- 양배추는 869 단위가 맞지 않아 당근 구간을 임시로 쓰며 등급이 "추정"입니다.
- 1362 가락과 대조(당근·양배추): "아래"와 "위"가 서로 반대로 나온 반월은 0건. 대신 당근은 10개 중 8개가 "근처"로, 종이에 "농협 확인"이 가장 많이 나옵니다.
- 1361 값을 다른 출처로 검증하지 않고 구간을 좁히면 안 됩니다(값이 10% 틀리면 판정이 절반쯤 뒤집힘).

## 5. hold 행과 종이

`supports.csv`에서 `status = hold`는 5행(2026-11-08 기준)입니다. 이유는 `notes`에 적혀 있습니다.

| 행 | 이유 |
|---|---|
| NAT-SAFETY-INS (농업인 NH안전보험) | 원문 대조 전(언론 근거) |
| NAT-PRICE-STAB-GO (정부 가격안정제 마늘·양파) | 원문 대조 전(언론 근거) |
| JEJU-CITRUS-PSTAB (노지감귤 가격안정관리제) | 원문 대조 전(언론 근거) |

종이에서의 뜻: hold 행의 **숫자는 찍지 않습니다.** 보험은 숫자 없이 "창구 확인"으로만 나옵니다. hold 행의 숫자가 종이에 있으면 인쇄 전 검사가 `HOLD_ROW`로 막습니다. `prior_year_reference`(26행)는 "작년 기준" 배지와 "○월쯤" 날짜로 찍고, `valid_to`가 지난 행은 `EXPIRED_ROW`로 막습니다. `confirmed`는 11행입니다.
